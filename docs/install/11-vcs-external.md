# Внешний ВКС

Используйте этот вариант, если локальный медиасервер не ставите. Аудио и видео идут через шлюз Unicomm.

Адрес шлюза в поставке: `lk-yc.unic.chat`.

## Что открыть

С сервера UnicChat — только исходящие соединения:

| Куда | Порт | Назначение |
|------|------|------------|
| `lk-yc.unic.chat` | 443/tcp | Сигналинг |
| `lk-yc.unic.chat` | 7881/tcp, 7882/udp | WebRTC |
| `lk-yc.unic.chat` | 50000–60000/udp | RTP |

Входящие порты 3478, 5349, 7880, 7881 и диапазоны RTP на сервере UnicChat для этого сценария не открывайте. Их слушает шлюз Unicomm, не ваш nginx.

Имена `mylk-yc.unic.chat`, `turn.mylk-yc.unic.chat`, `whip.mylk-yc.unic.chat` относятся к внешнему контуру. В `.env` UnicChat их нет.

## Чем это отличается от локального сервера

| | Внешний шлюз | Локальный сервер |
|--|--------------|------------------|
| Кто держит медиа | Unicomm | ваш хост |
| Входящие медиа-порты на UnicChat | не нужны | не на UnicChat, а на [хосте ВКС](12-vcs-local.md) |
| DNS | имена Unicomm | ваши `livekit` и `turn` |

Оба контура сразу не смешивайте: клиент должен знать один адрес медиасервера.

Проверка: совершите звонок между двумя клиентами вне вашей LAN. Если прямой UDP режется, внешний TURN на стороне Unicomm должен подхватить сессию без открытых входящих портов на UnicChat.
