# Требования

Проверьте этот список до клонирования и до `docker compose up`.

## Поддерживаемые версии

Значения совпадают с тегами в `multi-server-install/.env.example`. Другие теги не входят в эту матрицу, пока вы явно не согласуете их с Unicomm.

| Компонент | Версия в поставке |
|-----------|-------------------|
| ОС | Ubuntu 22.04 LTS или 24.04 LTS |
| Docker Engine | Актуальная стабильная ветка с [документации Docker](https://docs.docker.com/engine/install/) |
| Docker Compose | Плагин `docker compose` (v2), не отдельный бинарник `docker-compose` v1 |
| MongoDB | 4.4 (`IMAGE_MONGODB`). Для 5.x и новее нужен AVX |
| PostgreSQL | 12 (`IMAGE_POSTGRES`) — DocumentServer и Logger |
| MinIO | `RELEASE.2024-12-18T13-15-44Z` |
| Nginx (образ UnicChat) | тег `2.4.1` |
| DocumentServer | образ `uniceditor` |
| AppServer | `unic_chat_appserver:2.4.3` |
| RabbitMQ | тег `latest` в `.env.example` — зафиксируйте конкретный тег перед production |

Время на хостах синхронизируйте по NTP. Расхождение часов ломает TLS и реплику MongoDB.

## Лицензия

До начала установки запросите в Unicomm лицензию на продукт UnicChat. Лицензия одна на всю установку.

Без неё контейнеры запустятся, но продукт работать не будет. Сервер проверяет лицензию по `LICENSE_HOST` в `.env` (по умолчанию `https://push1.unic.chat/`). Откройте исходящий 443/tcp на этот адрес.

## Клонирование

```shell
git clone https://github.com/unicommorg/unicchat.enterprise.git
cd unicchat.enterprise
```

Дальше работайте в каталоге `multi-server-install/`.

## DNS

Зарегистрируйте имена до выпуска сертификатов. Примеры замените своими в `.env`.

| Назначение | Переменная | Пример |
|------------|------------|--------|
| Веб-интерфейс | `APP_SERVER_NAME` | `myapp.unic.chat` |
| MinIO | `MINIO_SERVER_NAME` | `myminio.unic.chat` |
| DocumentServer | `DOCUMENTSERVER_SERVER_NAME` | `myedt.unic.chat` |

На одном сервере все три A-записи указывают на IP этой машины. На нескольких серверах — на хост роли Nginx.

Для локального ВКС нужны отдельные имена. Их список — в [локальном ВКС](12-vcs-local.md).

## Ресурсы

Исходные конфигурации из поставки:

| Контур | Где | CPU | RAM | Диск |
|--------|-----|-----|-----|------|
| До 20 пользователей, всё на одной ВМ | один сервер | 4 × 1.7 ГГц, FMA3, SSE4.2, AVX 2.0 | 8 ГБ | 150 ГБ |
| 20–50 пользователей, приложение | отдельная ВМ | 4 × 1.7 ГГц, FMA3, SSE4.2 | 8 ГБ | 200 ГБ |
| 20–50 пользователей, БД | отдельная ВМ | 4 × 1.7 ГГц, FMA3, SSE4.2, AVX 2.0 | 8 ГБ | 100 ГБ |

Таблица ниже — планировочная оценка для заказа ВМ. Это не результат нагрузочного теста. Допущения: активны около 30% пользователей одновременно, сообщения и файлы умеренного размера, DocumentServer включён. С локальным ВКС добавьте отдельный хост медиасервера (минимум 4 vCPU и 8 ГБ RAM на 50 одновременных участников; Coturn и LiveKit не ставьте на тот же диск, что MongoDB).

| Пользователи | Без локального ВКС | С локальным ВКС |
|--------------|--------------------|-----------------|
| до 50 | App 4 vCPU / 8 ГБ / 200 ГБ; данные 4 vCPU / 8 ГБ / 200 ГБ | плюс медиасервер 4 vCPU / 8 ГБ |
| 100 | App 8 vCPU / 16 ГБ / 300 ГБ; MongoDB+MinIO 8 vCPU / 16 ГБ / 500 ГБ | плюс медиасервер 8 vCPU / 16 ГБ |
| 500 | App 16 vCPU / 32 ГБ; MongoDB 8 vCPU / 32 ГБ; MinIO 8 vCPU / 16 ГБ и отдельный диск | медиасервер от 16 vCPU / 32 ГБ |
| 1000 | Разнесите AppServer, MongoDB, MinIO, Knowledgebase; MongoDB от 16 vCPU / 64 ГБ; согласуйте схему с Unicomm до закупки | медиасервер считайте отдельно по числу одновременных комнат |

Рост файлового хранилища закладывайте отдельно от системного диска: объём MinIO ≈ число пользователей × средний объём вложений × срок хранения. Начните с 100 ГБ на бакет и смотрите заполнение до того, как диск превысит 70%.

Один сервер оставляйте для демо и теста. Для production используйте [несколько серверов](03-multi-node.md).

## Обязательные и необязательные компоненты

Обязательно:

- Push-шлюз Unicomm: исходящий 443/tcp на `push1.unic.chat`. Входящие порты для шлюза не открывайте.
- Приложения iOS, Android и Desktop ходят на ваш HTTPS (443/tcp).

Видеозвонки — один из двух контуров, не оба сразу без отдельного решения:

- [внешний шлюз Unicomm](11-vcs-external.md);
- [локальный LiveKit и Coturn](12-vcs-local.md).

Необязательно: свой SMTP и LDAP. Без них продукт ставится.

Дальше: [один сервер](02-single-node.md) или [несколько серверов](03-multi-node.md).
