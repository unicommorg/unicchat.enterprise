# Обновление и откат

Меняйте теги образов в `.env` (`IMAGE_*`). На всех серверах файл с тегами должен совпадать.

## Перед обновлением

1. Прочитайте примечания к версии от Unicomm. Несовместимые скачки (например MongoDB 4.4 → 5 без AVX и без миграции) не выполняйте в одном окне с обновлением приложения.
2. Снимите копию по [резервному копированию](08-backup-restore.md).
3. Зафиксируйте текущие теги: `cp .env .env.before-upgrade`.

## Порядок

На одном сервере:

```shell
docker compose pull
docker compose up -d
docker compose up -d --wait
```

На нескольких серверах тяните образы и пересоздавайте роли в том же порядке, что при установке: MongoDB, Logger, MinIO, Vault, Tasker, Knowledgebase, AppServer, Nginx. Базы данных обновляйте раньше приложения, если релиз это требует. Если релиз меняет только AppServer, перезапускайте AppServer и затем Nginx.

После старта проверьте миграции по логам:

```shell
docker compose logs --tail=200 unicchat-appserver
docker compose logs unicchat-documentserver | grep 'Installing plugins'
```

Дождитесь `Installing plugins, please wait...Done`, если обновлялся DocumentServer. Затем пройдите [критерии успеха](07-validation.md).

## Откат

1. Остановите обновлённые сервисы.
2. Верните теги из `.env.before-upgrade`.
3. Если новая версия уже записала данные, которые старая не читает, восстановите тома и дампы из копии, снятой до обновления. Одного отката тега недостаточно.
4. `docker compose pull` и `up -d` со старыми тегами.
5. Снова пройдите критерии успеха.

Не откатывайте MongoDB на более старый бинарник поверх каталога данных новой мажорной версии. В этом случае восстанавливайте дамп на чистый том.

## Несовместимость компонентов

Держите одну ревизию `.env` на все роли. Смешение тега AppServer новой поставки со старым Tasker или Vault не поддерживается, если release notes это не разрешают. При сомнении остановите обновление и верните предыдущий `.env`.
